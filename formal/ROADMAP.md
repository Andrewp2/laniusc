# Verified compiler roadmap

After the mini compiler (`MINI_COMPILER.md`). The rules there still hold: pure
Lanius, shallow extraction, the top-level theorem first, one simulation lemma
per pass, files that check in seconds. Each step records what it proves, what
it still trusts, proof lines against code lines, and check time.

| # | step | status |
|---|------|--------|
| 1 | Mini compiler lists proved against the list specs the extractor assumes | done: a cons list `List<T>`; each list operation is extracted with a Lean-checked spec theorem; `std::vec` specs move to step 10 |
| 2 | Extractor faithfulness: proof for the pure subset, at least a large difftest | difftests done: 3,006 programs end to end and 8,200 per-function calls (`fn_difftest.py`), no differences. The proof needs a Core heap model for `Box`, so it moves to step 6 |
| 3 | laniusc limits pure code hits at scale: per-allocation mmap and no free, `view` copying the tail, match arms without blocks or `if` | `<` match-arm parse fixed (fb6f3310); 1 GiB `MAP_32BIT` cap removed (70a4134f); `view` gone with the cons list. Open: a small-object allocator (needed by step 11; must keep the strace allocation-failure tests meaningful), block/`if` match arms, a nested `match` whose arms are `match`es does not get the expected type (`u8` result typed `i32`; `CmpOp.setcc` works around it) |
| 4 | The real verified compiler in `verified_compiler/`, pure style, top-level theorem first | first pass done: `compile_source` lowers a typed Core subset (i32/bool, operators, `let`, assignment, calls, `if`, `while`, `return`) to the mini IR; `compileSource_correct` proves it against Core's evaluator, composed with the mini compiler's theorem. It lives with the mini compiler in `formal/lani/mini/`; moving to `verified_compiler/` waits for step 5's features |
| 5 | Source features one at a time: structs, enums and `match`, `Vec`, generics (monomorphized) | structs done (scalar fields; literals, field reads/writes, copies, struct parameters). Enums and `match` done (scalar payloads; construction, copies, enum parameters, `let y = match x {...}` with one arm per variant and scalar arm values). Struct and enum returns done: the mini IR's calls and returns carry several slots (results replace the arguments, eax holds the last). Nested aggregates done: fields and payloads of any type (types nest through `List`, so the extractor emits Lean `mutual` blocks). `match` arms with statement bodies are out: Core's `match` is an expression with expression arms. Arms and field reads give whole structs and enums. Generics need nothing here: Core is monomorphic (`Ty` has no type variables). Next: `Vec`, which needs step 6 |
| 6 | Target memory model for aggregates and the heap; allocator spec | aggregates done in step 5 (a value is its fields' slots, laid out in order). (a) done: slots and the accumulator are 64-bit words; each operation carries a `Word`, `S32` (the 32-bit instruction, result zero-extended, signed comparisons) or `U64` (REX.W, unsigned comparisons); the front pass holds `i32` zero-extended and tests enum tags as `U64`. (b) done: `u8`, `u32`, `u64` and `usize` in the front pass, with literals, arithmetic masked to the type's width, unsigned comparisons, and casts to and from `i32` (sign-extending to 64 bits) proved against Core's `wrapUnsigned`/`wrapSigned`. (c) done: the mini IR has a byte heap with `alloc` (aligned bump, trap past the limit), `loadByte` and `storeByte`; on x86 the base, cursor and limit sit in r12, r13, r14; the front pass lowers Core's raw pointers, `alloc`, `loadByte`, `storeByte` and `dealloc` to these, proved through a Core heap to mini heap correspondence (the mini cursor is Core's `nextAddress`, starting at 1). (d) started: the mini IR has 32- and 64-bit little-endian heap word loads and stores (`loadWord`, `storeWord`), proved down to x86; the front pass lowers raw `i32` slices (`i32_slice_from_raw_parts`, element reads and writes at native 4-byte offsets), proved, and the type checker soundness covers them. Still to do: (d) typed raw slices of structs and enums for `Box`, then `Vec`, read and written at native layout offsets |
| 7 | Type checker soundness, which establishes the theorem's "well typed" premise | front pass done (`TypeSound`): `compileSource_wellTyped : compileSource sp = some binary → Typing.ProgramWellTyped sp.toCore`, with no other premise, for the `sp.toCore` of `compileSource_correct`. `compile_source` derives one struct or enum declaration per id from the program's types and rejects an id with two field or variant lists (`toCore` emits the declarations), and rejects a function body that does not end in `return` on every path (`SrcStmt.returns`). The counterexamples `idClash` and `noReturn` are now rejected (`compileSource ... = none` by `rfl`) |

| 14 | Trusted base: list every unproved assumption; test the x86 model against the CPU | first pass done: `TRUSTED_BASE.md` lists the Lean kernel and axioms, the statement's definitions, Core as the meaning of Lanius, the front end, extraction and the prelude, the x86 model, the existential theorem against a nondeterministic `Step`, and the caller/loader premises. `x86_model_test.py` runs every emitted instruction form natively and through `decode`/`execute`: 56,006 cases, no disagreements. Order of work: 3, 1, 2, 4, then 5 to 14. Steps 5 to 7 are the long stretch;
12 is where the proofs start making laniusc itself more trustworthy.
