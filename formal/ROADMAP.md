# Verified compiler roadmap

After the mini compiler (`MINI_COMPILER.md`). The rules there still hold: pure
Lanius, shallow extraction, the top-level theorem first, one simulation lemma
per pass, files that check in seconds. Each step records what it proves, what
it still trusts, proof lines against code lines, and check time.

| 6 | Target memory model for aggregates and the heap; allocator spec | aggregates done in step 5 (a value is its fields' slots, laid out in order). (a) done: slots and the accumulator are 64-bit words; each operation carries a `Word`, `S32` (the 32-bit instruction, result zero-extended, signed comparisons) or `U64` (REX.W, unsigned comparisons); the front pass holds `i32` zero-extended and tests enum tags as `U64`. (b) done: `u8`, `u32`, `u64` and `usize` in the front pass, with literals, arithmetic masked to the type's width, unsigned comparisons, and casts to and from `i32` (sign-extending to 64 bits) proved against Core's `wrapUnsigned`/`wrapSigned`. (c) done: the mini IR has a byte heap with `alloc` (aligned bump, trap past the limit), `loadByte` and `storeByte`; on x86 the base, cursor and limit sit in r12, r13, r14; the front pass lowers Core's raw pointers, `alloc`, `loadByte`, `storeByte` and `dealloc` to these, proved through a Core heap to mini heap correspondence (the mini cursor is Core's `nextAddress`, starting at 1). (d) started: the mini IR has 32- and 64-bit little-endian heap word loads and stores (`loadWord`, `storeWord`), proved down to x86; the front pass lowers raw `i32` slices (`i32_slice_from_raw_parts`, element reads and writes at native 4-byte offsets), proved, and the type checker soundness covers them; it also lowers raw slices of structs whose fields are `i32`, `bool`, `usize` or `ptr`, at Core's native offsets (one 8-byte word a field, elements growing down), and raw slices of enums with word payloads (a tag word, then the variant's payload words, chosen by tag tests), proved; and `ptr + usize`, `ptr - usize` (Core's wrapping pointer offset), which places a typed view's top element. Core change C4 done (10-22): Core's native layout is laniusc's (a value's word 0 is its highest word, fields, payloads and view elements descend from it, slices are 3 words, every scalar kind is one word; TRUSTED_BASE.md section 3); the mini compiler's element bases and field addresses subtract (`Var - i·8w`, `base - 8j`), proved again, and Core's native-store library (`NativeStoreSpec`, a slot ending 8 bytes above word 0) and its tests follow it. C3 done (10-22): struct fields and enum payloads in slices may also be `u8`, `u32` (4-byte loads and stores), `u64` and `isize` (8-byte), proved; the oracle generates them (300 programs, no disagreements). F8 done (10-22): struct fields and enum payloads in slices may be declared structs of such fields, nested; both sides lay a value out by its leaves, the word fields with nested structs flattened in order, proved; an effectful expression may also copy a struct local's aggregate field (`EPure(Field(x, j))`); the oracle generates nested struct fields and payloads (frontend_difftest.py does not yet). F8 stage 2 done (10-22): a slice element is any word type (`word_type`: scalars, structs of word types, enums of word payloads, nested in any order); the front pass loads and stores it by recursion on the type, as Core's `words?`/`fieldOffset`/`payloadOffset` lay it out (an enum: its 4-byte tag at word 0, the variant's payload from word 1, chosen by tag tests); `Mini/ElementLayout.lean` (`FieldReads`, `FieldWrites`) replaces `FlatLayout`, proved; the oracle generates structs and enums nested in each other (300 programs, no disagreements). Still to do: `Vec` |
