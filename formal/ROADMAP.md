# Verified compiler roadmap

After the mini compiler (`MINI_COMPILER.md`). The rules there still hold: pure
Lanius, shallow extraction, the top-level theorem first, one simulation lemma
per pass, files that check in seconds. Each step records what it proves, what
it still trusts, proof lines against code lines, and check time.

## Entirely verified (from 2026-10-28)

The goal: no unproved implementation code between a program's source text
and its x86 bytes. What stays trusted is specification only, each a short
statement a reader must accept: the Lean kernel and its three axioms; Core as
the meaning of Lanius; the lexical rules, the grammar and the reading (what
a parse tree means); the x86 model; and what the operating system provides
at startup. Everything that computes is proved against those. Feature work
(`Vec` in the front pass, modules in the front pass, more optimizer passes)
is not part of this goal.

### V2 plan (decided 10-28)

Core's traps split three ways. Checked traps must make the compiled code
fault (`ud2` or `#DE`, both `Fault` in the x86 model, which has no step from
them): `arrayBounds`, `invalidShift`, `divisionByZero`,
`signedDivisionOverflow`, `allocationFailure`. Undefined traps are a premise
of the theorem, as undefined behaviour is in CompCert: `rawMemoryBounds`,
`invalidPointer`, `doubleFree`, `allocatorContract` (raw memory errors,
which only a check of every raw access could catch). Impossible traps are
contradicted by the lowering's invariants: `typeMismatch`,
`uninitializedLocal`, `missingReturn`, `nonExhaustiveMatch`. Running out of
heap or of stack is a fault too.

- V2a. Checks in the compiled code: index below length (`arrayBounds`),
  shift amount below the width (`invalidShift`), and a stack-limit check
  in the prologue against a limit register. A failed check divides by
  zero, so the mini IR needs no trap statement. The forward theorems carry
  over: on a returning run every check passes.
  Shifts are done (10-29): each statement first tests its expressions'
  guard (`SrcExpr.guard`, 1 when every shift Core evaluates has its amount
  below the width) as `if g { s } else { 1 / 0 }`, so a passing check
  changes no slot; a guard that is `Lit(1)` emits nothing, and the self
  compiler's shifts are all constant. `SrcExpr.guard_sound`
  (Mini/Guard.lean): a Core run that completes makes the guard 1. Index
  checks are done too: a slice is two slots, its address and its length
  (below `2 ^ 31`, so a negative `i32` index fails the unsigned test), and
  every element read or write first tests `index < length`. The stack
  check is done: the prologue ends with `cmp r15, rsp; jbe +2; ud2`, so
  a frame that reaches below the limit in r15 faults before it writes a
  slot; with enough stack every check passes (`stackCheck_det`,
  Mini/HeapSteps.lean), and otherwise one fails (`stackCheck_fails`). A call's pushes
  (`8 * args + 16` bytes) land before the callee's check, so the window
  reaches `binary.guard` bytes below r15 (`StackAt`).
  The x86 contract is now "returns, or the window is short of the need
  and the run stops at a fault" (`Faults`: every run that stops, stops at
  a `ud2` or `#DE`), and `Det` also says no run stops early (`Live`).
  With `stackNeed depth ≤ window` the forward theorems are unchanged.
- V2b. `Stops prog depth env heap stmt n` on the mini IR: the run faults,
  or does not finish within `n` ticks (a tick is a loop iteration or a
  call). Done (10-29, `Mini/Stops.lean`): `Stops` stops at an allocation
  past the limit (from a cursor within it) or an undefined division, and
  the compiled code of a `Stops` statement is `AStops` on the abstract
  machine for the same `n` (`compileStmt_stops`, `compileFunc_stops`).
- V2c. Mini to x86: `Stops` for every `n` gives an x86 run that never
  returns (determinism up to flags, `rsp` below the entry `rsp` until the
  return). Done (10-29, `Mini/StopsCorrect.lean`): `compileProgram_stops`,
  with `Program.Stops` for every `n`, says `Faults`: every run that stops,
  stops at a fault. Each abstract step takes at least one x86 step, so
  `AStops n` gives `FaultsWithin n` (no stop before `n` steps but at a
  fault); a failed `bump` reaches its `ud2` and an undefined division
  raises `#DE` (`bump_fails`, `div_fails`), and a call that does not
  return is `StopsContract`, by induction on the depth. `function_enter`
  (Mini/Correct.lean) is the prologue both contracts share. Proving
  `bump_fails` found a bug: `bump` added the size to the rounded cursor in
  64 bits, so a size near 2^64 wrapped, passed the limit test and moved
  the cursor back. `bump` now tests the carry (`add r11, rax; jb` to the
  `ud2`), 58 bytes.
- V2d. Core to mini: a Core run that fails at every fuel (out of fuel, a
  trap that is not undefined, or a heap past the limit; `Fails`,
  Mini/Fails.lean) gives `Stops` for every `n`. Done (10-29):
  `stmtStops_all` (Mini/EvalStops.lean), by induction on `n` and then on
  the statement and its effectful expressions (`effStops_all`), with a
  loop's next iteration and a callee's body at `n - 1`; and
  `compileSource_stops` (Mini/SourceStops.lean): a failing Core call makes
  the compiled code `Faults`. Standard axioms. `typeMismatch` became an
  undefined trap (SEMANTIC_DECISIONS.md), and the proof found that
  `slice[i] = v` evaluated `v` before the bounds check; it now checks
  first, as Core does. F1 made `lowerSlice` reject element types past
  Core's native layout limits (`lowerSlice_layout`), so `typeMismatch` is
  left only for invalid bit patterns read from raw memory.
- V2e. `compileSource_behaviour`: an x86 run that returns is a Core run
  that returns, with the same results, unless Core hits an undefined trap.
  Done (10-29, Mini/SourceStops.lean): a run of the compiled `f` from its
  entry that ends at a state with no step that is not a fault (the
  caller's exit) comes from a Core call that completes within the heap
  limit, whose results `compileSource_correct` gives, or that reaches an
  undefined trap. Standard axioms. The gate's `traps` step runs checked
  traps, stack and heap exhaustion natively (each faults) and a loop that
  never ends (it runs on).
