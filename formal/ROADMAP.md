# Verified compiler roadmap

After the mini compiler (`MINI_COMPILER.md`). The rules there still hold: pure
Lanius, shallow extraction, the top-level theorem first, one simulation lemma
per pass, files that check in seconds. Each step records what it proves, what
it still trusts, proof lines against code lines, and check time.

| # | step | status |
|---|------|--------|
| 1 | Mini compiler lists proved against the list specs the extractor assumes | done: a cons list `List<T>`; each list operation is extracted with a Lean-checked spec theorem; `std::vec` specs move to step 10 |
| 2 | Extractor faithfulness: proof for the pure subset, at least a large difftest | difftests done: 3,006 programs end to end and 8,200 per-function calls (`fn_difftest.py`), no differences. The proof needs a Core heap model for `Box`, so it moves to step 6 |
| 3 | laniusc limits pure code hits at scale: per-allocation mmap and no free, `view` copying the tail, match arms without blocks or `if` | `<` match-arm parse fixed (fb6f3310); 1 GiB `MAP_32BIT` cap removed (70a4134f); `view` gone with the cons list. Open: a small-object allocator (needed by step 11; must keep the strace allocation-failure tests meaningful), block/`if` match arms, a nested `match` whose arms are `match`es does not get the expected type (`u8` result typed `i32`; `CmpOp.setcc` works around it) |
| 4 | The real verified compiler in `verified_compiler/`, pure style, top-level theorem first | first pass done: `compile_source` lowers a typed Core subset (i32/bool, operators, `let`, assignment, calls, `if`, `while`, `return`) to the mini IR; `compileSource_correct` proves it against Core's evaluator, composed with the mini compiler's theorem. It lives with the mini compiler in `formal/lani/mini/`; moving to `verified_compiler/` waits for step 5's features |
| 5 | Source features one at a time: structs, enums and `match`, `Vec`, generics (monomorphized) | structs done (scalar fields; literals, field reads/writes, copies, struct parameters). Enums and `match` done (scalar payloads; construction, copies, enum parameters, `let y = match x {...}` with one arm per variant and scalar arm values). Struct and enum returns done: the mini IR's calls and returns carry several slots (results replace the arguments, eax holds the last). Nested aggregates done: fields and payloads of any type (types nest through `List`, so the extractor emits Lean `mutual` blocks). `match` arms with statement bodies are out: Core's `match` is an expression with expression arms. Arms and field reads give whole structs and enums. Generics need nothing here: Core is monomorphic (`Ty` has no type variables). Next: `Vec`, which needs step 6 |
| 6 | Target memory model for aggregates and the heap; allocator spec | aggregates done in step 5 (a value is its fields' slots, laid out in order). (a) done: slots and the accumulator are 64-bit words; each operation carries a `Word`, `S32` (the 32-bit instruction, result zero-extended, signed comparisons) or `U64` (REX.W, unsigned comparisons); the front pass holds `i32` zero-extended and tests enum tags as `U64`. (b) done: `u8`, `u32`, `u64` and `usize` in the front pass, with literals, arithmetic masked to the type's width, unsigned comparisons, and casts to and from `i32` (sign-extending to 64 bits) proved against Core's `wrapUnsigned`/`wrapSigned`. (c) done: the mini IR has a byte heap with `alloc` (aligned bump, trap past the limit), `loadByte` and `storeByte`; on x86 the base, cursor and limit sit in r12, r13, r14; the front pass lowers Core's raw pointers, `alloc`, `loadByte`, `storeByte` and `dealloc` to these, proved through a Core heap to mini heap correspondence (the mini cursor is Core's `nextAddress`, starting at 1). (d) started: the mini IR has 32- and 64-bit little-endian heap word loads and stores (`loadWord`, `storeWord`), proved down to x86; the front pass lowers raw `i32` slices (`i32_slice_from_raw_parts`, element reads and writes at native 4-byte offsets), proved, and the type checker soundness covers them; it also lowers raw slices of structs whose fields are `i32`, `bool`, `usize` or `ptr`, at Core's native offsets (one 8-byte word a field, elements growing down), and raw slices of enums with word payloads (a tag word, then the variant's payload words, chosen by tag tests), proved. Still to do: (d) nested aggregates in slices, then `Vec` |
| 7 | Type checker soundness, which establishes the theorem's "well typed" premise | front pass done (`TypeSound`): `compileSource_wellTyped : compileSource sp = some binary → Typing.ProgramWellTyped sp.toCore`, with no other premise, for the `sp.toCore` of `compileSource_correct`. `compile_source` derives one struct or enum declaration per id from the program's types and rejects an id with two field or variant lists (`toCore` emits the declarations), and rejects a function body that does not end in `return` on every path (`SrcStmt.returns`). The counterexamples `idClash` and `noReturn` are now rejected (`compileSource ... = none` by `rfl`) |
| 8 | Front end by translation validation: the parser's tree re-prints to the source tokens | |
| 9 | Modules and separate compilation; linking correctness | done at the mini IR level: `compile_module` compiles one module alone into an object (each function's machine code, with a rel32 hole for every call to an import), `link_objects` checks each import's owner, function and arity and fills the holes; `link_eq` (`Mini/Link.lean`) proves `(compileModules ms).bind linkObjects = ((linkProgram ms).bind compileProgram).map Binary.executable`, so `compileProgram_correct` and its determinism hold for linked executables with no new premises (`linked_correct`, `linked_deterministic`). `link_difftest.py`: 2,000 random multi-module programs, 1,353 linked, 647 rejected by both, 3,492 holes filled, no differences. laniusc builds the linker and fn_difftest (299 functions) finds no differences. Open: modules in the front pass |
| 10 | Stdlib (`std::vec`, `std::set`, `std::map`) proved against functional specs | |
| 11 | Self-hosting: laniusc-built and self-built verified compiler agree byte for byte | |
| 12 | The verified compiler as an oracle for laniusc on the stdlib and fuzzed programs | started: `oracle_difftest.py` compiles random front-pass programs (integers, `bool`, structs, enums, `match`, loops, calls) with `compileSource`, runs the image natively, and compares each call with the laniusc build of the same program and with a reference interpreter: 2,300 programs, 18,400 calls, no disagreements. To do: heap and raw slices, then the stdlib (needs generics and modules) |
| 13 | Optimizations as unverified passes checked by proved validators | first pass done: `optimize_program` (not proved) folds constants, applies unit and zero identities, takes constant branches and drops no-op statements over the mini IR; `validate` (proved, `Validate.lean`) walks both programs, so `validate p q = true` gives every returning run of `p` a run of `q` with the same result, heap and depth (`Returns.validated`). `compile_source` keeps the optimized program only when it is accepted, and `compileSource_correct` covers that with an unchanged statement. `optimize_test.py`: 2,000 random programs, every change accepted (1,563), every mutant rejected, front-pass images 44.6% smaller, 8,000 native calls agree; laniusc builds it, and fn_difftest (265 functions) and the oracle (300 programs) find no differences. Open: passes over the front pass's IR |
| 14 | Trusted base: list every unproved assumption; test the x86 model against the CPU | first pass done: `TRUSTED_BASE.md` lists the Lean kernel and axioms, the statement's definitions, Core as the meaning of Lanius, the front end, extraction and the prelude, the x86 model, the existential theorem against a nondeterministic `Step`, and the caller/loader premises. `x86_model_test.py` runs every emitted instruction form natively and through `decode`/`execute`: 56,006 cases, no disagreements. A probe outside the emitted forms found a decoder defect (`88 /r` without REX took reg 4-7 as SPL..DIL, the CPU stores AH..BH); fixed, `decode` now refuses those bytes. Word loads and stores added: 61 forms, 0 disagreements. `Step` is now proved deterministic on compiled bytes up to the free flags: `compileProgram_deterministic` and `compileSource_deterministic` (`Mini/Determinism.lean`) say every `n`-step run from the entry state ends with the same registers, rip and memory as the run that returns, so it returns the same results (`decode_unique`, `Det` threaded through `Simulation`'s contracts). Open: a verified loader |

Order of work: 3, 1, 2, 4, then 5 to 14. Steps 5 to 7 are the long stretch;
12 is where the proofs start making laniusc itself more trustworthy.
