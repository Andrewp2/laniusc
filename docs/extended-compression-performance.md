# Compression performance evidence

These samples were collected on 2026-10-23 from the Lanius
[compress-bytes application](extended-compress-bytes.md). Native execution and
GPU compilation are measured separately. No compiler implementation changed
for this milestone.

## Native application execution

The native process was pinned to CPU 8, with one warmup and five measured
processes for each row. Timings include binary pipes, process startup, argument
capture, bounded input/result owners, encoding/decoding, container checksums and
output. The compiler benchmark finished before this run. Other desktop work
was not controlled; the full observed range is retained.

Input repeats `bytes(0..255)` followed by
`entry,id,value\nexample,123,456\n`, truncated to the stated size. Encode outputs
were independently decompressed and checked. Decode inputs were independently
generated by Python zlib, and every decoded byte was checked.

| Format | Operation | Decoded bytes | Compressed bytes | Median | Range |
| --- | --- | --- | --- | --- | --- |
| zlib | Encode | 65,536 | 988 | 40.670 ms | 24.693–41.450 ms |
| zlib | Decode | 65,536 | 667 | 6.525 ms | 5.777–9.440 ms |
| zlib | Encode | 1,048,576 | 11,265 | 355.278 ms | 302.632–375.922 ms |
| zlib | Decode | 1,048,576 | 4,956 | 50.724 ms | 49.345–51.226 ms |
| gzip | Encode | 65,536 | 1,000 | 22.991 ms | 22.773–27.846 ms |
| gzip | Decode | 65,536 | 679 | 8.364 ms | 7.665–9.720 ms |
| gzip | Encode | 1,048,576 | 11,277 | 349.868 ms | 344.052–351.294 ms |
| gzip | Decode | 1,048,576 | 4,968 | 100.749 ms | 98.328–104.660 ms |

The different compressed sizes reflect the two encoders' choices. The Lanius
profile selects a fixed Huffman or stored representation; the reference writer
can generate dynamic trees. Gzip decoding also performs CRC-32, while zlib
performs Adler-32. These are interoperability and scale measurements, without
a comparison of native throughput to another library.

The owned encoder measures the raw result before allocating exact output, and
the caller-buffer encoder independently checks its atomic capacity contract.
This repeats matching work. The decoder grows its output and replays the
current member; it retains no resumable bit/tree state. Those choices bound
failure behavior and ownership but leave performance work for future APIs.

The [raw encoder measurements](extended-deflate.md#native-measurements) separately
cover 512 KiB random, repetitive and textual data, including incompressible
stored-block output. Whole-input byte limits and output ownership are described
in [compression containers](extended-compression.md).

## Existing stdlib compiler benchmark

`examples/stdlib_gpu_perf.rs` now accepts an optional final `SOURCE_ROOT`.
It uses the compiler's source-root entry point for both standard-only and
extended entries. The normal five arguments still express a standard-only
benchmark; the sixth supplies the extension root. The summary records its
source-root count.

`LANIUS_PERF_REBUILD_ENTRY=1` copies and touches the entry between samples.
The compiler process/device stays warm and imported files remain unchanged.
One warmup and three measured entry rebuilds produced:

| Entry | User roots | Emitted bytes | Median | Range | Native output |
| --- | --- | --- | --- | --- | --- |
| `sample_programs/library/compress_bytes.lani` | `extended` | 298,500 | 232.515 ms | 229.616–255.416 ms | Exact empty gzip stream, 20 bytes |
| `tests/fixtures/stdlib_foundation/adler32_contracts.lani` | None | 26,478 | 164.553 ms | 163.309–166.164 ms | Exit 0, empty stdout/stderr |

The compression entry's current import closure contains 23 source files,
approximately 187 KB and 4,329 text lines. This is the real application with
its codecs, argument parser, owners and native I/O. The harness checks the
emitted executable's status and output. Fully cold imported-library rebuilds,
the canonical 1 MB synthetic workloads and cross-compiler speed comparisons
require separate measurements; these rows make no claim about them.

Reproduce the extended-entry measurement using the existing build directory:

```sh
mkdir -p target/stdlib-work
python3 - <<'PY'
from pathlib import Path
Path('target/stdlib-work/compress-empty-gzip').write_bytes(
    bytes([31, 139, 8, 0, 0, 0, 0, 0, 0, 255, 3, 0]) + bytes(8))
PY
timeout --kill-after=2s 100s env \
  CARGO_TARGET_DIR="$PWD/target/stdlib-build" CARGO_INCREMENTAL=0 \
  CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 \
  LANIUS_PERF_REBUILD_ENTRY=1 \
  cargo run --locked --example stdlib_gpu_perf -- \
  sample_programs/library/compress_bytes.lani stdlib \
  target/stdlib-work/compress-empty-gzip 1 3 extended
```

The Python snippet writes an expected-output fixture; it implements no codec.
All benchmark/test commands remain bounded below two minutes. GPU compilation
of these native executables does not establish GPU-kernel execution.
