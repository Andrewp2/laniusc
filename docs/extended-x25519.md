# X25519

`ext::x25519` implements the X25519 function specified in
[RFC 7748 section 5](https://www.rfc-editor.org/rfc/rfc7748.html#section-5).
The original Lanius arithmetic uses fixed storage, without an external field
implementation, generic big integers, allocation, or 128-bit arithmetic.

```lanius
pub enum Error { Bounds, InvalidScalarLength, InvalidPointLength, LowOrder }
pub struct Key { bytes: [u8; 32] }
public_key(scalar: View<u8>) -> Result<Key, Error>
shared_secret(scalar: View<u8>, point: View<u8>) -> Result<Key, Error>
```

Both inputs must contain exactly 32 bytes. Logical bounds for both shared
inputs precede size checks; scalar size precedes point size. Physically
backed views may have nonzero starts and native strides. Inputs stay
unchanged and are not retained. Returned keys contain independent byte arrays.

The implementation clamps a local scalar copy, masks the point's high bit,
reduces noncanonical coordinates modulo 2^255−19, and emits a canonical
little-endian coordinate. `public_key` uses coordinate 9. `shared_secret`
aggregates all 32 result bytes before rejecting an all-zero value as
`LowOrder`, following the check described in
[RFC 7748 section 6.1](https://www.rfc-editor.org/rfc/rfc7748.html#section-6.1).

## Field arithmetic and bounds

Every stored field value is canonical, with 16 radix-2^16 `u64` limbs;
limbs 0 through 14 are below 65536 and limb 15 is below 32768. Addition
adds limbs. Subtraction forms `a + 2p − b`, keeping every coefficient
nonnegative. Multiplication uses 16-by-16 schoolbook convolution: each
coefficient has at most 16 products of values below 65536, hence is below
2^36. Folding the upper half through 2^256 ≡ 38 modulo p leaves lower
coefficients below 2^42. The top has no folded degree-31 term and is below
2^37. Multiplication by 121665 stays below 2^33 per limb.

Three fixed carry passes normalize each result. The first leaves limb 0
below 2^28 and all other limbs within their radices. The second can carry
at most one through the top; if that happens, the normalized top becomes
zero and the third pass resolves the low-limb addition of 19. Otherwise
the third pass is unchanged. The normalized value is below 2^255, so at
most one subtraction of p is needed. Radix subtraction adds 65536 before
subtracting each prime limb and borrow. Its borrow stays in {0,1}; a mask
selects the original or subtracted limbs. These bounds fit well within u64.

The Montgomery ladder has exactly 255 steps. Scalar bits affect only XOR
masks used to swap fixed-index limbs. Field operations have fixed loops and
no data-dependent divisions. Inversion raises to p−2 with 255 squarings and
253 multiplications; its only conditional skips are the public exponent
positions 4 and 2. This describes source control flow and addresses. Runtime
timing and generated machine-code side channels require separate analysis;
the source structure alone is not a constant-time certification.

## Verification

All three focused gates passed on **x86_64 Linux native ELF generated by the
GPU compiler**, with empty allocation traces. The ordinary Alice/Bob consumer
imports the public API without projecting the error enum. The tests compare complete keys with
libsodium's Curve25519 functions and a separate Python integer-field RFC
ladder. Sodium error output is unspecified and is never used as an oracle.
For noncanonical points, the Python field model determines RFC behavior and
sodium also checks the corresponding canonical coordinate.

Executed cases include both section 5.2 vectors, section 6.1 Alice/Bob keys
and agreement, all 19 noncanonical coordinates, ignored scalar-bit and
point-bit toggles, low-order rejection, malformed range/length priority,
packed and strided offsets with guards, and retained/mutated returned key
copies across later calls. A separate bounded gate checks iteration 1 and
1000; the million-iteration vector is outside this focused gate. Other
targets and user GPU kernels have not been admitted.

| Gate | Accepted evidence | Elapsed |
| --- | --- | ---: |
| Ordinary consumer | Alice/Bob public keys and both agreement directions; no caller error projection | 4.11 s |
| Independent models | 298 commands covering encoding, arithmetic, layouts, errors and returned-value independence | 8.37 s |
| RFC iterations | Iteration 1 and 1000; 1001 ladder invocations in one native process | 12.69 s |

The three gates ran in separate driver invocations, producing **three strict
ELFs and three native processes**. The driver can share its protocol ELF
through `OnceLock` when its tests run together, but that was not the accepted
invocation shape. The fresh joint build of four Rust test targets took
1.60 s. These are correctness observations, not isolated throughput results.
